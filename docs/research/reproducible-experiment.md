> 示例文章：这里演示科研记录的推荐结构，正式使用时请替换为自己的实验内容。

实验记录的最低标准，不是“我还记得当时做了什么”，而是数周后仅凭记录仍能解释结果，并尽可能重现同一组输出。

## 记录目标

一份有效记录应当回答四个问题：

1. 为什么做这次实验？
2. 输入、环境和参数是什么？
3. 实际发生了什么？
4. 结果如何改变下一步决策？

## 实验身份

给每次实验分配稳定编号，并关联代码提交：

```text
实验编号: EXP-20260812-01
代码版本: 4f37c2a
数据版本: dataset-v3
负责人: Lu Zichao
```

编号应当出现在日志目录、结果图和实验记录中。这样即使文件被单独转发，也能追溯到上下文。

## 保存运行环境

### 软件环境

至少记录运行时、核心依赖与锁文件。Python 项目可以保存：

```powershell
python --version
python -m pip freeze > artifacts/EXP-20260812-01/requirements.txt
git rev-parse HEAD
git status --short
```

如果工作区有未提交修改，单独保存补丁或先提交实验分支。只记录 commit SHA 无法恢复未提交代码。

### 数据与随机性

记录数据集来源、清洗版本、切分策略和随机种子。对于深度学习实验，还应注明硬件型号、驱动和加速库版本。相同种子并不保证不同硬件或库版本得到逐位一致的结果，因此需要同时记录容差范围。

## 配置与命令

让启动命令保持完整，避免只写“使用默认配置”：

```powershell
python -m src.train `
  --config configs/baseline.yaml `
  --seed 42 `
  --output artifacts/EXP-20260812-01
```

参数较多时，将配置写入受版本控制的 YAML 或 TOML 文件，日志中保存最终展开后的配置。

## 结果与结论

结果应包含主要指标、对照组与测量条件：

| 实验 | 验证集准确率 | 训练时长 | 备注 |
| --- | ---: | ---: | --- |
| baseline | 82.4% | 41 min | 原始配置 |
| proposed | 83.1% | 47 min | 其余条件相同 |

一次提升不等于稳定结论。需要报告重复次数、均值、方差，并检查增益是否来自数据泄漏或评价流程变化。

## 复盘清单

- 这次实验验证或排除了哪个假设？
- 是否有异常样本、失败运行或被忽略的指标？
- 结果是否足以改变当前判断？
- 下一次实验只改变哪个变量？
- 哪些步骤可以自动化为脚本或测试？

可复现记录的价值不只是复现结果，还在于减少重复试错，并让失败实验也能成为后续决策的证据。
